# Google Colab Integration Skill

Guides running BRX SYSTEM on Google Colab free/pro tiers with zero local installation.

## When to Use
- User asks to run BRX on Colab
- User needs a cloud demo without local setup
- User wants multi-agent orchestration in Colab
- User asks for local models inside Colab CPU/GPU

## Prerequisites
- Google account (free Colab tier supported)
- API keys stored in Colab Secrets (recommended)

## Setup Steps

### Option A: API Mode (Recommended for Free Tier)
1. Open `colab/BRX_System_Normal.ipynb` or `BRX_System_MultiAgent.ipynb`
2. Run cells sequentially
3. Add API keys to `Secrets` (OpenAI, DeepSeek, Google, Anthropic)
4. Execute tunnel cell (ngrok) for public URL

### Option B: Local Model Mode (CPU)
1. Open `colab/BRX_System_Local.ipynb`
2. Install Ollama via provided cell
3. Pull a lightweight model: `phi`, `tinyllama`, `qwen:0.5b`, `gemma:2b`
4. Run build & start cells

### Option C: GPU Mode (Colab Pro)
1. Change runtime to GPU (`Runtime > Change runtime type`)
2. Use Ollama with larger models: `llama3.2`, `mistral`, `qwen2.5`
3. Enable CUDA in Ollama via environment variable

## Environment Variables for Colab
```bash
NODE_ENV=production
DATABASE_URL=sqlite://./colab.db
BRX_MODE=multi_agent        # or 'local' / 'normal'
BRX_MAX_AGENTS=5
BRX_SHARED_MEMORY=true
BRX_LIGHT_MODE=true         # reduces RAM usage on free tier
```

## Troubleshooting
- **RAM limit exceeded**: Enable `BRX_LIGHT_MODE=true` and restart
- **ngrok tunnel fails**: Ensure NGROK_AUTH_TOKEN is set in Colab Secrets
- **Model download slow**: Use models under 2GB for free CPU tier
- **SQLite locked**: Stop previous runtime and factory reset if needed

## Security Notes
- Never hardcode API keys in notebook cells; use Colab Secrets
- Disable ngrok tunnel when not needed
- Use `.env` files generated by notebook; do not commit them
